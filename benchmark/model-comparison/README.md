# Phase 4.6 — запуск, изоляция и воспроизводимость

Этот инструмент не меняет интерфейс World Lens и не подключает ingestion. Он останавливается перед генерациями без явно утверждённых бюджета и plan SHA. Основная production-модель не переключается. Существующие production reservations/база не читаются и не очищаются.

## Подготовленные файлы

- `dataset.json`: 100 новых для проекта GOV.UK публикаций; страты 15/15/15/10/10/10/10/10/5. Категории и сложные признаки ожидают человеческой проверки.
- `corpus/`, `source-snapshots/`: локальные полные тексты и происхождение, исключены из Git до проверки исключений лицензии. URL, hashes и attribution остаются в manifest.
- `ground-truth.json`: фактическая разметка, пока pending. `ground-truth.template.json`: безопасный шаблон для клонирования. `null` не означает отсутствие событий.
- `adjudication.json`: ручное выравнивание и семантическая оценка предсказаний; шаблон в `adjudication.template.json`.
- `config.json`, `dry-run.json`, `model-availability.json`: фиксированные IDs, настройки, смета, доступность metadata API.
- `runs-ministral.json`, `runs-gemini.json`, `errors.json`: локальные raw export-файлы, не Git; до запуска пусты.
- `metrics.json`, `cost-analysis.json`, `comparison.md`: воспроизводимые сводки, пока без вымышленных quality результатов.
- `state/<plan SHA>/`: отдельные SQLite, полные HTTP requests/responses и результаты. Полностью исключено из Git.

PDF-механизма в проекте нет, поэтому основной отчёт Markdown, как разрешено ТЗ.

## Команды без генераций

```powershell
npm ci
# На другом checkout: восстановить корпус из подготовленного annotation package.
# Альтернатива — явно загрузить только 100 замороженных URL:
npm run compare:fetch-corpus
npm run compare:dry
npm run compare:score
```

`compare:fetch-corpus` — одноразовое восстановление фиксированного списка, не поиск новых новостей. Источник с изменившимся HTML/text hash отклоняется; заменять его текущим текстом нельзя. Предпочтителен архив из annotation package. Этот шаг не нужен в CI; тесты используют безопасные metadata/синтетические проверки.

`compare:dry` строит каждое тело запроса тем же request builder, что production provider, но не вызывает HTTP generation. Ключи только проверяются на наличие. Доступность моделей проверена metadata GET отдельно; это не генерационный smoke.

## Только после явного разрешения человека

```powershell
npm run compare:run -- --paid --approve-budget=10 --plan=SHA_FROM_REVIEWED_DRY_RUN --phase=smoke
# После успешного smoke можно продолжить все фазы с тем же plan:
npm run compare:run -- --paid --approve-budget=10 --plan=SHA_FROM_REVIEWED_DRY_RUN
npm run compare:score
```

Наличие ключей не является подтверждением бюджета. Не запускать команды выше до явного ответа пользователя. Параметр cap может быть меньше configurable hardBudgetCapUsd, но не больше; для повышения лимита обновить config, заново показать dry-run и получить новый approval.

Smoke4, main200, consistency120, reprint20 =344 логических jobs. Максимум688 HTTP attempts при одной дополнительной429 попытке. Отрицательные dedup-кандидаты используют уже полученные main ответы без доплаты. 5xx/timeouts/отсутствие usage останавливают дальнейшие вызовы с сохранением консервативного резерва. Известный429 учитывается как отклонение с нулевым inferred charge, retry ограничен provider policy. Цена по токенам — оценка, не billing.

Две модели чередуются на одной статье; settings/prompts не меняются внутри серии. Gemini wire schema допускает меньше decoder constraints, серверная логическая схема одна. Температура0 и output cap6000 одинаковы, но thinking входит в лимит Gemini. Это ограничение сравнения отражено в отчёте.

## Сохранение и возобновление

Каждая HTTP attempt сначала резервируется в атомарном JSON checkpoint, затем дописывается полный ответ/usage. Общий бюджет проверяется по всем моделям и фазам. Дополнительно остаётся штатный per-database provider budget. Один `state/run.lock` предотвращает два одновременных процесса. При аварии lock удаляется только после проверки, что предыдущий процесс завершён.

Повтор команды с тем же plan пропускает все завершённые `*.result.json`, включая неудачные jobs: неудачный результат не перезапускается ради улучшения метрик. У job с HTTP history, но без финального checkpoint, автоматический повтор запрещён: сначала восстановить полученный ответ офлайн или сверить незавершённый расход. Даже если это требует ручного восстановления, уже оплаченный запрос не повторяется автоматически. Нельзя обнулять uncertain и стирать историю, чтобы продолжить.

Изменение runtime, compiled code, tools, config, prompt, schema, статьи или её происхождения меняет plan SHA. Для нового plan нужно отдельное разрешение. Для анализа старой серии восстановить соответствующий frozen revision; никогда не смешивать серии. Внутренние application cache ключи не меняются. Свежие consistency generations получают разные isolated DB по повтору, а не поддельные даты/URL публикаций.

## Разметка и scoring

Полный quality отчёт требует человеческого ground truth и adjudication; автоматический scorer не решает семантическое выравнивание. Инструкции: `ANNOTATION.md`. Разметка не должна использовать Ministral/Gemini как окончательного арбитра. До неё качество/парные интервалы остаются null. Операционные метрики после реальных вызовов можно считать независимо.

Level A — original raw events до проверок. Level B — Valid claims с CanonicalEvent, без второй копии одного canonical внутри статьи; неподтверждённый MergeCandidate остаётся withheld. Ничего не становится Verified/Ready. Все виды ошибок и причины отклонений сохраняются.

Тесты: `npm run test:backend`; новый benchmark test не вызывает провайдеров. Основной frontend и промпты не менялись.
